# MUSA 已完成实验结果

8 张 MTT S5000（每卡约 80 GB），Qwen3-32B BF16，8 个 TP1 完整副本。整体客户端并发 16，每卡最多 3 条在途请求；不是每张卡并发 16。输入 8192 token，共享前缀 7936 token，8 文档，热点比例 25%，输出分别为 32、64、128 token。单轮，种子 33962，每个单元 64 条学习请求和 128 条正式请求，9 个单元合计 1728 条请求均成功。

InfiniLM 每卡 128×256 token，vLLM 每卡 2048×16 token，两者 KV 预算均为 32768 token。每单元新启动模型池；同一单元的正式阶段继承学习阶段缓存。三个输出长度之间轮换方法顺序，不等于同场景内多次配对复测。vLLM 为实际使用的 MUSA 适配环境。

32、64 输出时，V3 相对 vLLM 吞吐分别提升 21.79%、8.16%，平均 TTFT 分别降低 54.96%、49.30%。128 输出时，V3 吞吐比 vLLM 低 0.22%，比 V2 低 0.89%；平均 TTFT 比 V2 高 20.32%。64、128 输出的 p95 TTFT 均高于 vLLM，不能将平均值优势表述为所有请求都更快。

学习请求用于建立缓存和路由状态，不是模型训练。合计吞吐为两阶段输出 token 总数除以两阶段计时之和，不计模型启动、探针和校准，不能称为完整部署冷启动性能。128 输出的 0.09% 差异视为近似持平。
